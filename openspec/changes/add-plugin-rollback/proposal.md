# Proposal

## Why

完整回档会同时覆盖 DSH 安装目录与用户目录，代价大、影响面广。实际最常见的故障是某个插件升级后出问题，用户只想把插件恢复到存档时的版本，不想回退 DSH 本体，也不想改动会话、技能、凭据等用户数据。现有流程没有这个选项，用户只能二选一：要么整体回档，要么手动折腾 node_modules。

## What Changes

- 设置页的回档确认增加模式选择：「完整回档」与「仅回滚插件」。
- 恢复脚本启动后先选择模式：`1` 完整回档、`2` 仅回滚插件，然后再执行原有的 `Y/N` 确认。
- 仅插件模式只恢复插件 profile：`package.json`、`pnpm-lock.yaml`、`cordis.patch.yml` 与 `node_modules`；DSH 安装目录、用户目录与运行时依赖都不改动。
- 仅插件模式只解压压缩包中的 profile 部分，不整包解压，减少恢复所需空间与时间；回档前快照也只保存 profile 配置。
- 仅插件模式沿用完整回档的确认、任意键退出、压缩包校验、插件自身排除与 junction 重建，并在开始前提示"插件数据与 DSH 版本不会回退"。
- 从设置页触发时把模式作为参数传给脚本，脚本跳过菜单但仍要求确认；用户双击脚本且未带参数时显示模式菜单。
- 存档格式不变；只要存档包含 profile，就能使用仅插件模式，无需重新备份。

## Capabilities

### New Capabilities

- `plugin-rollback`: 在完整回档之外提供仅恢复插件 profile 的回档模式，覆盖模式选择、恢复范围、快照范围、兼容提示、保护规则与设置页入口。

### Modified Capabilities

无。`crash-restore` 目前仍是未归档的变更，本次以独立能力描述新增模式，共用行为沿用其契约，不重复定义。

## Impact

- 新插件 `dsh-crash-backup` 的 `client.js`（回档模式选择与文案）、`lib/scripts.js`（脚本菜单、`-Mode` 参数与仅插件分支）、新增或调整的恢复模块（按前缀解压、仅 profile 恢复）。
- 恢复脚本 `RESTORE.ps1` 增加模式判断与仅插件分支；`RESTORE.cmd` 透传参数。
- 存档格式与索引字段不变；`manifest.json` 已有 profile 信息，可直接判断是否支持仅插件模式。
- 兼容性：仅插件模式在存档 DSH 版本与当前版本不一致时存在插件 API 不兼容风险，需要提示但不阻止用户继续。
- 用户数据：仅插件模式不写 `home`，因此不会回退技能、会话、凭据与插件数据目录；这一点必须在 UI 与脚本中说明，避免用户误以为插件设置也回到了存档时。
