# Design

## Context

`add-crash-backup` 定义了新插件的完整回档契约（见 `specs/crash-restore/`），但尚未实现，主 `openspec/specs/` 目录仍为空。因此本次把"仅回滚插件"作为独立能力 `plugin-rollback` 描述，复用完整回档已有的确认、任意键退出、校验、插件自身排除与链接重建，只新增模式选择与恢复范围两件事。

已知约束：

- 压缩包内插件内容位于 `profile/<profile>`，与 `install/`、`home/`、`runtimes/` 平级。
- profile 内 `node_modules` 约 1.2 GB，完整解压整包需要约 2.6 GB 临时空间；仅解压 profile 可显著降低空间与时间。
- 恢复脚本是独立 PowerShell 5.1 脚本，无法假设 DSH 可启动或插件 API 可用。
- 现有 `link:` 依赖在存档中会被物化为普通目录，需要靠清单重建。

## Goals / Non-Goals

**Goals:**

- 让"只换回插件"成为一次可预期、可取消、可回退的操作，且不触碰安装目录与用户数据。
- 设置页与双击脚本两个入口都能使用该模式，行为一致。
- 复用完整回档的安全机制，不引入第二套确认与退出逻辑。

**Non-Goals:**

- 不回退插件数据目录、用户配置、DSH 版本与运行时依赖。
- 不提供"只回滚某一个插件"的细粒度选择。
- 不做插件级差异计算或版本对比 UI。

## Decisions

### 1. 作为独立能力而不是修改 crash-restore

`crash-restore` 还在未归档的变更里，主 spec 不存在，OpenSpec 的 MODIFIED 需要已有主 spec。写成 `plugin-rollback` 可以独立校验与归档；共用行为引用 `crash-restore`，不复制一遍。

- 备选"等 add-crash-backup 归档后再改 crash-restore"：会阻塞本次规划，且用户现在就要这个能力。
- 备选"把内容塞回 add-crash-backup"：用户明确要求新增一个变化。

### 2. 模式由脚本参数与菜单共同决定

`RESTORE.ps1` 增加 `-Mode full|plugins`：带参数时跳过菜单，无参数时显示 `1/2` 菜单。`RESTORE.cmd` 原样透传参数。

- 设置页触发时传 `-Mode plugins` 或 `-Mode full`，避免用户重复选择。
- 双击场景没有 UI，菜单是唯一入口；这也满足崩溃时脚本独立可用的要求。
- 备选"生成两个脚本"：会破坏"存档文件夹只有压缩包和恢复脚本"的约定。
- 备选"仅设置页支持插件模式"：崩溃时无法使用，正好丢掉了最重要的场景。

### 3. 仅插件模式按前缀解压

`tar -xf <zip> -C <tmp> "profile/<profile>"`，只解出插件目录；随后对 `profile/<profile>` 做镜像恢复。

- 需要先验证 bsdtar 对 zip 成员的路径前缀匹配行为；若不可靠，回退为"解压全部但只复制 profile"，并把空间预检相应调整。
- 备选"整包解压"：实现简单但多占用约 1.4 GB 临时空间与一倍解压时间。

### 4. 快照与校验范围同步收窄

仅插件模式只把当前 profile 的 `package.json`、`pnpm-lock.yaml`、`cordis.patch.yml` 复制到 `_pre-restore/<时间戳>-plugins/`；校验仍检查压缩包可读与 `profile/<profile>` 存在，但不检查安装目录相关内容。

- 这样失败时不会因为"安装目录校验不过"而误判整个存档不可用。

### 5. 版本差异只警告不阻止

从 `install/version`（当前）与 `manifest.json` 的 `dshVersion`（存档）比较；不一致时显示提示，允许继续或取消。

- 阻止会让"插件升级坏了、但 DSH 也升级过"的场景无法自救。
- 提示要具体说明可能出现插件加载失败，并建议必要时改用完整回档。

### 6. 恢复后必须重启 DSH

node_modules 与 patch 变更不会被运行中的 DSH 重新加载，结束提示明确要求重启，而不是"可以继续使用"。

### 7. 不支持时在 UI 禁用、在脚本报错

存档缺少 `profile/<profile>` 时，设置页禁用仅插件选项并显示原因；脚本收到 `-Mode plugins` 且找不到该目录时，在动任何文件前退出。

## Risks / Trade-offs

- [bsdtar 对 zip 成员的按前缀解压可能不如预期] → 实现时先用真实存档验证；失败则降级为整包解压并在预检中按整包计算空间。
- [仅回滚插件后 DSH 版本不匹配，插件加载失败] → 版本差异提示 + 失败后建议完整回档；`_pre-restore` 保留回档前 profile。
- [插件数据仍是新版本格式，与旧插件不匹配] → 在 UI 与脚本中明确提示；不擅自回退用户数据。
- [profile 镜像会删除存档之后新装的其它插件] → 这是"回到存档时插件集"的预期行为，提示中说明；本插件自身始终排除。
- [用户误以为插件设置也回退了] → 两个入口都显示"插件数据不会回退"，并在成功后再次说明。

## Migration Plan

- 纯增量功能，不改存档格式，已有新格式存档可直接使用。
- 回滚本变更：移除模式菜单与 `-Mode` 分支，恢复脚本回到完整回档单一流程；存档与索引无变化。
